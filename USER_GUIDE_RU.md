## 1. Введение и возможности

**Notion Terminal MCP** — это шлюз между искусственным интеллектом (Notion Custom Agents, Claude, Cursor, Antigravity) и вашей операционной системой. Сервер работает по официальному стандарту **Model Context Protocol (MCP)** через транспорт **Streamable HTTP**.

### Ключевые возможности:
- 🖥️ **Desktop GUI (Liquid Glass Dark)**: Красивый графический интерфейс с контролем статуса, логами в реальном времени и удобными кнопками копирования.
- ⚡ **Исполнение команд (Terminal)**: Запуск PowerShell / CMD команд с нативной поддержкой UTF-8 (корректно отображает кириллицу и спецсимволы).
- 📁 **Работа с файлами (Filesystem)**: Чтение, запись, частичная точечная замена блоков кода (`file_replace`), умный поиск/grep (`file_search`), создание папок, перемещение и удаление.
- 🗂️ **Управление проектами (Workspace)**: Переключение активной папки (`workspace_set_cwd`), позволяющее агенту работать с несколькими проектами в одном репозитории или папке через короткие относительные пути.
- 🌐 **Встроенный Ngrok-туннель**: Мгновенный проброс публичного защищенного HTTPS-адреса для Notion без ручной возни с портами роутера.
- ☁️ **Бесплатный Cloudflare Quick Tunnel**: Готовый скрипт `start-public.ps1` для запуска публичного туннеля вообще без учетной записи и регистрации.
- 🌍 **Автоматизация браузера (Browser Automation)**: Открытие веб-страниц в установленном Chrome или Edge, выполнение произвольного JavaScript, клики, ввод текста, тестирование локальных сервисов (`http://localhost:...`) и снятие скриншотов.
- 🛡️ **Защита и безопасность**: Защита от timing-атак при сверке токенов, валидация Host-заголовков (защита от DNS Rebinding), настраиваемая изоляция файлов (Sandbox).

## 2. Способы запуска

### Вариант А: Desktop Приложение (.exe) *(Рекомендуется)*

В папке `release/` доступны готовые файлы для Windows:
- **`release/Notion Terminal MCP 1.0.0.exe`** — портативная версия (не требует установки, запускается сразу).
- **`release/Notion Terminal MCP Setup 1.0.0.exe`** — классический инсталлятор Windows.

**Как запустить:**
1. Запустите `.exe` файл.
2. Откройте **Settings (.env)** и укажите:
   - `MCP_API_KEY` (или нажмите сгенерировать токен).
   - `NGROK_ENABLED=true`, `NGROK_AUTHTOKEN` и ваш `NGROK_DOMAIN` (если используете статический домен Ngrok).
3. Нажмите **Start Server**.

---

### Вариант Б: Запуск из командной строки (Node.js)

Если вы предпочитаете запускать сервер в консоли или на сервере:

```powershell
# 1. Установка зависимостей
npm install

# 2. Первоначальная настройка .env
Copy-Item .env.example .env
npm run token # выведет готовый криптостойкий ключ для вставки в .env

# 3. Сборка TypeScript и запуск CLI-сервера
npm run build
npm run start

# 4. Запуск графического Desktop приложения (Electron)
npm run app:start

# 5. Сборка самостоятельных .exe файлов в папку release/
npm run package:portable   # Чисто Portable .exe (без установки)
npm run package:installer  # Чисто Установщик (Setup wizard)
npm run package:exe        # Собрать оба варианта сразу
```

---

### Вариант В: Бесплатный Cloudflare Tunnel (`start-public.ps1`) *(Без регистрации)*

Если у вас нет учетной записи Ngrok или вы не хотите регистрироваться, в репозиторий включен готовый скрипт автоматического туннелирования через **Cloudflare Quick Tunnels**:

```powershell
.\start-public.ps1
```

**Что делает скрипт полностью автоматически:**
1. Если `.env` отсутствует, запускает `setup.ps1` и генерирует криптографически стойкий 32-байтный ключ.
2. Проверяет наличие `tools/cloudflared.exe`. При отсутствии скачивает официальный бинарник с репозитория Cloudflare и **проверяет цифровую подпись Authenticode** (сертификат Cloudflare, Inc.).
3. Компилирует TypeScript (`npm run build`).
4. Поднимает сервер на `http://127.0.0.1:3000` и проверяет endpoint `GET /health`.
5. Запускает безопасный туннель Cloudflare и получает публичный адрес вида `https://<random>.trycloudflare.com`.
6. Выводит в консоль красивый баннер с готовым URL (`https://<random>.trycloudflare.com/mcp`) и заголовком `Authorization: Bearer <токен>`.
7. При нажатии `Ctrl+C` корректно завершает и сервер, и процесс туннеля.

### Назначение карточек копирования:
1. **Notion Public URL (Ngrok `/mcp`)**: Готовый HTTPS-адрес со встроенным путем `/mcp`. Это именно тот адрес, который нужно вставлять в Notion.
2. **Local MCP URL**: Локальный адрес `http://127.0.0.1:3000/mcp` (для локальных тестов или дебага через MCP Inspector).
3. **Raw Token**: Чистый секретный ключ (без приставки `Bearer `). Есть иконка «глазок» для просмотра и кнопка копирования.
4. **Full Authorization Header**: Полная строка вида `Bearer <токен>`.
5. **Ngrok Base Domain**: Базовый адрес домена ngrok без путей.

### Графическое окно настроек (Settings Modal):
Нажатие на кнопку **Settings (.env)** открывает визуальный редактор параметров сервера:
- **API Key**: ваш секретный токен доступа. Кнопка с иконкой кубика/генерации позволяет мгновенно создать новый криптостойкий 64-символьный hex-ключ.
- **Сетевые параметры (`PORT` и `HOST`)**: порт (по умолчанию `3000`) и адрес привязки (`127.0.0.1`).
- **Режим доступа (`FULL_ACCESS`)**:
  - `false` (Выключен): агент надежно заперт внутри папки `FILES_ROOT`. Попытки выйти за ее пределы блокируются.
  - `true` (Включен): агент получает полный доступ ко всей файловой системе Windows с правами текущего пользователя.
- **Папка песочницы (`FILES_ROOT`)**: путь к локальной рабочей директории (по умолчанию `%APPDATA%\notion-terminal-mcp\config\workspace`).
- **Туннель Ngrok**:
  - `NGROK_ENABLED`: галочка активации туннеля при старте сервера.
  - `NGROK_AUTHTOKEN`: ваш личный токен с сайта Ngrok.
  - `NGROK_DOMAIN`: фиксированный бесплатный домен (например, `my-custom-subdomain.ngrok-free.app`).
- **Разрешенные хосты (`ALLOWED_HOSTS`)**: перечень доменов, разделенных точкой с запятой, для защиты от атак DNS Rebinding.
- **Системные лимиты**:
  - `COMMAND_TIMEOUT_MS`: максимальное время выполнения команды (по умолчанию 120 000 мс / 2 минуты).
  - `MAX_OUTPUT_BYTES`: лимит буфера вывода консоли (по умолчанию 1 МБ).
  - `MAX_FILE_BYTES`: максимальный размер одного файла при чтении/записи (по умолчанию 10 МБ).

### Системный трей (System Tray) и скрытие с панели задач:
Приложение поддерживает полноценную работу в фоновом режиме в системном трее Windows (рядом с часами):
- **Кнопка «Свернуть в трей»** (`ArrowDownToLine` в верхнем правом углу): мгновенно скрывает окно приложения и убирает его с панели задач Windows, освобождая место.
- **Закрытие на крестик (`X`)**: безопасно сворачивает приложение в трей, сохраняя соединение MCP-сервера с Notion активным.
- **Клик левой кнопкой мыши по иконке в трее**: мгновенно показывает или скрывает главное окно.
- **Контекстное меню (правый клик по иконке в трее)**:
  - *Показать Notion Terminal / Скрыть окно в трей*
  - *Индикатор статуса сервера* (Работает / Остановлен / Запуск)
  - *Открыть Ngrok Live URL* (если активен туннель)
  - *Управление сервером*: Запустить / Остановить / Перезапустить сервер
  - *Выход из приложения*: полное завершение процесса и безопасная остановка сервера.

## 4. Подключение к Notion (пошагово)

1. **Запустите сервер** в приложении (кнопка **Start Server**).
2. Убедитесь, что загорелся зеленый бейдж **Ngrok Public Live**.
3. В приложении нажмите кнопку **Copy** в блоке **Notion Public URL (Ngrok /mcp)**.
4. Откройте **Notion**:
   - Перейдите в настройки вашего ИИ-агента или в **Settings & Members** → **Connections** → **Add Connection** (или **Custom MCP**).
   - В поле **Server URL** вставьте скопированный URL:
     ```text
     https://<ваш-домен>.ngrok-free.dev/mcp
     ```
   - В поле **Authentication**:
     - Header Name: `Authorization`
     - Header Value: нажмите кнопку **Copy Header** в приложении (вставит `Bearer <ваш_ключ>`) или **Copy Token** (если Notion сам подставляет Bearer).
5. Нажмите **Connect / Test**. Notion автоматически считает доступные функции и подключит их к вашему агенту.

## 5. Архитектура и безопасность

```
 Notion Agent (Cloud)
         │
         │  HTTPS (JSON-RPC over Streamable HTTP)
         ▼
 Public Tunnel (Ngrok или Cloudflare)
         │
         ▼
 Notion Terminal MCP (Local Node.js/Electron Engine)
  ├── 1. Host Header Check (защита от DNS Rebinding)
  ├── 2. Timing-Safe Auth Check (защита от утечки ключа по таймингу)
  ├── 3. Structured Audit Logger (логирование действий в UI)
  └── 4. Tool Handlers (Терминал / Файлы / Проекты / Браузер)
```

### Песочница (Sandbox) vs Полный доступ (Full Access)

- **`FULL_ACCESS=false` (Режим по умолчанию / Рекомендуется)**:
  - Все операции агента изолированы внутри папки `FILES_ROOT` (по умолчанию папка `./workspace`).
  - Любые попытки выхода через `../`, системные ссылки или абсолютные пути к диску `C:\Windows` или `C:\Users` блокируются сервером.
  - Рабочая директория по умолчанию для терминала также заперта в `FILES_ROOT`.
- **`FULL_ACCESS=true` (Полный доступ к хосту)**:
  - Агент может открывать, редактировать и выполнять команды в любых папках вашей системы с правами вашей учетной записи Windows.

### Туннелирование: Ngrok и Cloudflare

1. **Встроенный SDK Ngrok (`@ngrok/ngrok`)**:
   - Включается прямо в Desktop приложении или через `NGROK_ENABLED=true` в `.env`.
   - Не требует установки сторонних утилит — туннель создается программно в том же процессе.
   - Поддерживает бесплатный фиксированный статический домен (`NGROK_DOMAIN`), поэтому адрес подключения в Notion не меняется при перезапусках.
2. **Cloudflare Quick Tunnel (`start-public.ps1`)**:
   - Полностью бесплатный альтернативный способ без регистрации и без создания учетных записей.
   - Автоматически скачивает официальный подписанный исполняемый файл `cloudflared.exe` и создает безопасный туннель на домене `trycloudflare.com`.

## 6. Справочник MCP Инструментов (20 инструментов)

Всего сервер предоставляет **20 инструментов**, оптимизированных для работы с ИИ-агентами:

### 🖥️ 1. Исполнение команд (Terminal Execution)
| Название инструмента | Назначение | Основные параметры |
|---|---|---|
| `terminal_execute` | Выполнение команд в PowerShell или CMD с поддержкой UTF-8, настраиваемыми таймаутами и завершением дерева дочерних процессов | `command` (строка), `shell` (`powershell`/`cmd`), `cwd` (папка), `timeout_ms` (макс. 900 000 мс) |

### 📁 2. Файловые операции (Filesystem Operations)
| Название инструмента | Назначение | Основные параметры |
|---|---|---|
| `file_search` | Поиск файлов по glob-маске (`*.ts`) и/или поиск текста/regex внутри содержимого (Grep) | `path`, `pattern` (glob), `query` (текст), `case_sensitive`, `max_results` (макс. 1000) |
| `file_replace` | Безопасная точечная замена блоков текста/кода без риска повреждения остального файла | `path`, `target` (старый фрагмент), `replacement` (новый фрагмент), `allow_multiple` |
| `file_read` | Чтение текстовых (UTF-8) или бинарных (Base64) файлов с поддержкой смещения и пагинации | `path`, `encoding` (`utf8`/`base64`), `offset`, `length` |
| `file_write` | Создание, перезапись или дописывание (`append`) файлов с автосозданием недостающих папок | `path`, `data`, `encoding`, `append` |
| `file_list` | Получение списка файлов и директорий (рекурсивно или плоским списком) с размерами | `path`, `recursive`, `max_entries` (макс. 10 000) |
| `file_stat` | Получение метаданных файла/папки (размер, дата создания, изменения, режим) | `path` |
| `file_mkdir` | Создание директории со всеми недостающими промежуточными родительскими папками | `path` |
| `file_move` | Переименование или перенос файлов/папок с опциональной перезаписью | `source`, `destination`, `overwrite` |
| `file_delete` | Безвозвратное удаление файла или папки (для непустых папок нужен флаг `recursive: true`) | `path`, `recursive` |

### 🗂️ 3. Управление рабочей областью (Workspace Management)
| Название инструмента | Назначение | Основные параметры |
|---|---|---|
| `workspace_get_cwd` | Запрос текущей активной рабочей директории (`cwd`) и базового пути песочницы (`files_root`) | *(без параметров)* |
| `workspace_set_cwd` | Переключение активной рабочей папки (например, на подпапку проекта `"sandustry"` или `src`), что позволяет агенту использовать короткие относительные пути | `path` (подпапка или относительный/абсолютный путь) |

### 🌐 4. Автоматизация браузера (Browser Automation)
| Название инструмента | Назначение | Основные параметры |
|---|---|---|
| `browser_open` | Запуск браузера хоста (Google Chrome или Microsoft Edge) и открытие URL. По умолчанию открывает видимое окно (`headless: false`) для визуального контроля | `url` (адрес), `headless` (`false`/`true`), `browser` (`chrome`/`edge`) |
| `browser_navigate` | Переход по новому адресу в активной вкладке браузера | `url`, `wait_until` (`load`/`domcontentloaded`/`networkidle0`), `timeout_ms` |
| `browser_evaluate` | Выполнение произвольного кода JavaScript или асинхронных выражений в контексте страницы с возвратом JSON | `script` (строка JS-кода) |
| `browser_click` | Клик по HTML-элементу по CSS-селектору | `selector`, `timeout_ms` |
| `browser_type` | Ввод текста в элементы input или textarea с опцией предварительной очистки | `selector`, `text`, `clear`, `timeout_ms` |
| `browser_get_content` | Извлечение отрендеренного текста, HTML-кода DOM или заголовка страницы | `type` (`text`/`html`/`title`), `selector` (опционально) |
| `browser_screenshot` | Снятие скриншота видимой области или всей страницы целиком (в файл PNG или base64) | `path` (путь к PNG, опционально), `full_page` (boolean) |
| `browser_close` | Безопасное закрытие запущенного браузера и освобождение ресурсов | *(без параметров)* |

Полные JSON-схемы для LLM-агентов описаны в файле [`AGENTS.md`](AGENTS.md).

## 7. Частые вопросы и решение проблем

#### В: Чем отличается туннель Ngrok от Cloudflare Quick Tunnel?
**О**: 
- **Ngrok** позволяет закрепить бесплатный постоянный домен (например, `myproject.ngrok-free.app`). Это означает, что однажды настроив адрес в Notion, вам не придется менять его при перезапусках сервера.
- **Cloudflare Quick Tunnel (`start-public.ps1`)** работает мгновенно и вообще не требует регистрации или токена, но выдает случайный адрес `*.trycloudflare.com` на каждую сессию запуска.

#### В: Как агент переключается между разными проектами?
**О**: Агент может вызвать инструмент `workspace_set_cwd(path: "frontend")` или `workspace_set_cwd(path: "backend")`. После этого все файловые операции (`file_read`, `file_replace` и т.д.) и команды `terminal_execute` автоматически выполняются в контексте выбранного проекта без необходимости вводить длинные абсолютные пути.

#### В: Почему в браузере при открытии ссылки пишет `{"status":"ok",...}`, а не интерфейс сайта?
**О**: Это MCP API сервер для агентов, а не веб-сайт. Корень `/` и `/health` возвращают JSON статус сервера, а запросы от Notion поступают на `/mcp` методом POST/GET с заголовком авторизации.

#### В: Что делать, если при запуске ошибка Ngrok `ERR_NGROK_...`?
**О**: Проверьте в окне **Settings (.env)** правильность указания `NGROK_AUTHTOKEN`. Если токена нет, получите его бесплатно на [dashboard.ngrok.com](https://dashboard.ngrok.com/get-started/your-authtoken).

#### В: Как сбросить или изменить API ключ?
**О**: В приложении откройте **Settings (.env)**, нажмите кнопку генерации ключа (иконка с кубиком) и сохраните настройки. Новый ключ мгновенно применится.

#### В: Где сохраняются настройки при использовании `.exe`?
**О**: В портативной и установленной версии настройки `.env` безопасно сохраняются в профиле пользователя:
`%APPDATA%\notion-terminal-mcp\config\.env`.
